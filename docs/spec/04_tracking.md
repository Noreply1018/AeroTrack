# 04. 跟踪规格

## 跟踪目标

跟踪模块负责把逐帧检测结果转换为序列级目标轨迹。v1 默认跑通 SORT，ByteTrack 使用相同输入输出规约预留；当 ByteTrack 接入后，应能在不修改评估和可视化模块的情况下参与对比。

## 跟踪输入

跟踪模块只读取项目统一检测结果，不读取 YOLO 原始输出。输入字段为：

```text
sequence_id, frame_id, class_id, score, x1, y1, x2, y2
```

跟踪应按 `sequence_id` 分组独立运行，避免不同序列之间的目标 ID 混用。

v1 默认在每个 `sequence_id` 内继续按 `class_id` 分组独立跟踪，减少不同类别检测框互相匹配造成的 ID 和类别污染。若后续实验需要跨类别统一跟踪，必须通过 tracker config 显式开启，并在实验摘要中标记。

## 统一跟踪结果

跟踪模块必须输出统一跟踪结果文件。v1 统一结果默认使用 CSV，每条结果至少包含：

```text
sequence_id, frame_id, track_id, class_id, score, x1, y1, x2, y2
```

默认文件名为 `tracks.csv`，并写入当前实验目录的 `tracks/` 下。

`track_id` 由跟踪器生成，并在同一序列内保持一致。不同序列之间不要求 ID 全局唯一。

## SORT baseline

SORT 是 v1 默认跟踪 baseline。配置至少包含：

1. 最小检测置信度。
2. 最大丢失帧数。
3. 最小确认帧数。
4. IOU 匹配阈值。

默认参数应写入 tracker config，而不是硬编码在脚本中。

## ByteTrack 接口

ByteTrack 接入时必须复用统一检测输入和统一跟踪输出。ByteTrack 允许使用高低置信度检测分层策略，但该策略只能存在于 ByteTrack adapter 内部，不能改变项目全局检测结果格式。

## 跟踪可视化

跟踪可视化应基于统一跟踪结果生成。图像或视频上至少显示：

1. 目标框。
2. `track_id`。
3. 类别信息。
4. 可选轨迹线。

## 失败处理

跟踪模块遇到以下情况应显式失败并给出错误信息：

1. 检测结果文件不存在。
2. 检测结果缺少必要字段。
3. 同一序列内帧号无法排序。
4. 坐标非法或目标框面积为负。
5. 跟踪器输出无法转换为统一格式。
