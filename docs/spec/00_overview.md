# 00. 项目概览

## 项目定位

本项目面向雷达感知研究在数据组织、结果对比与流程复现中的工程缺口，构建一个检测-跟踪端到端 ML 实验闭环。项目不做一次性的单模型演示，而是形成一套可重复运行、可替换组件、可沉淀结果的雷达目标检测与跟踪实验基线。

v1 固定采用 CARRADA 数据集的 Range-Angle 表示作为主要实验输入。项目通过统一数据接口、检测结果接口、跟踪结果接口和实验输出目录，使不同检测模型、跟踪器和后续雷达表示能够在一致口径下完成对比、ablation 与复核。

## 最终目标

项目最终交付的是工程化实验基线，而不是单个脚本或单次推理结果。v1 完成后应具备以下能力：

1. 将 CARRADA Range-Angle 数据和标注转换为 YOLO 可训练、可推理的数据格式。
2. 使用 YOLO 完成雷达目标检测训练与推理，并输出统一检测结果。
3. 将检测结果接入 SORT 跟踪模块，并为 ByteTrack 预留同接口接入。
4. 计算 detection metrics 和 tracking metrics，支持统一口径下的结果对比。
5. 生成检测可视化、跟踪可视化、轨迹回放和失败样例材料。
6. 通过配置和脚本复现实验流程，保留配置、日志、结果和指标。

## v1 范围

v1 必须完成：

1. 数据集固定为 CARRADA。
2. 雷达表示固定为 Range-Angle。
3. 检测器以 YOLO 系列模型为主。
4. 跟踪器完整跑通 SORT。
5. ByteTrack 预留同输入输出规约；若实现成本可控，则纳入默认对比。
6. 输出统一的检测结果、跟踪结果、指标结果和可视化结果。
7. 提供少步骤实验脚本，覆盖数据准备、检测推理、跟踪、评估和可视化。

v1 不做：

1. 不接入真实雷达硬件。
2. 不从零实现 YOLO、SORT 或 ByteTrack 的核心算法。
3. 不追求工业级实时性能。
4. 不承诺适配所有雷达数据集和所有雷达表示。
5. 不把论文发表、专利申请或硬件部署作为验收条件。

## 验收摘要

v1 达成条件：

1. 能从 CARRADA Range-Angle 数据生成 YOLO 可用数据集。
2. 能完成 YOLO 推理，并导出统一检测结果。
3. 能用 SORT 基于检测结果生成统一跟踪结果。
4. 能输出 precision、recall、F1、mAP50、MOTA 等核心指标；IDF1、ID switches、track fragmentation 等 ID 类指标在标注 ID 不稳定时必须输出不可用状态和原因。
5. 能生成检测和跟踪可视化结果。
6. 能通过一个实验配置复现完整流程。
7. 每次实验目录包含配置、结果、指标、可视化和日志。

## 设计原则

1. 固定 v1 范围，先把 CARRADA Range-Angle baseline 做扎实。
2. 所有模块通过统一文件格式衔接，避免检测器或跟踪器输出相互污染。
3. 所有实验必须可复现，配置、日志和输出不能只存在于临时命令行。
4. 指标和可视化同等重要，既要能量化对比，也要能解释失败原因。
5. 后续扩展通过 adapter 和配置完成，避免重写主流程。
