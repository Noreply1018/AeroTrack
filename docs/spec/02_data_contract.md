# 02. 数据契约

## 数据源

v1 数据源固定为 CARRADA 数据集，雷达表示固定为 Range-Angle。数据准备模块负责从本地 CARRADA 根目录读取样本、标注和序列信息，并生成训练、推理、评估和可视化所需的中间产物。

本项目不把 CARRADA 数据集提交进 git。数据根目录通过配置指定，默认位于 `data/carrada/`。

## Range-Angle 图像生成

v1 固定使用一种可复现的 Range-Angle 转图像策略作为训练和推理输入：

1. 将 Range-Angle 数值按配置化规则归一化到 8-bit。
2. 保存为三通道 PNG，便于直接接入 YOLO 框架。
3. 检测框坐标以保存后的 PNG 图像尺寸为准。
4. 若图像生成过程发生 resize、padding 或裁剪，必须同步转换标注坐标并记录转换参数。
5. 色图仅用于可视化检查，不作为默认训练输入。

归一化规则必须写入 dataset config，并随每次实验配置一起归档。

## 数据准备输出

数据准备阶段应生成以下产物：

1. YOLO 可读取的数据集目录。
2. train / val / test 划分文件。
3. 类别定义文件。
4. 原始标注到检测框标注的转换记录。
5. 样本索引表。
6. 标注可视化检查图。

## 样本索引

样本索引表用于连接原始数据、模型输入和评估目标。推荐字段：

```text
sample_id, sequence_id, frame_id, split, representation, image_path, label_path
```

字段含义：

1. `sample_id`：项目内部样本唯一标识。
2. `sequence_id`：CARRADA 序列标识。
3. `frame_id`：序列内帧标识。
4. `split`：`train`、`val` 或 `test`。
5. `representation`：v1 固定为 `range_angle`。
6. `image_path`：转换后图像路径。
7. `label_path`：检测标签路径。

## 检测标注

YOLO 标签用于训练，项目内部标注用于评估和可视化。内部标注推荐字段：

```text
sequence_id, frame_id, object_id, class_id, x1, y1, x2, y2
```

坐标统一使用图像像素坐标，`x1, y1` 为左上角，`x2, y2` 为右下角。若原始标注无法稳定提供 `object_id`，则检测评估可以不依赖该字段；跟踪评估需要 ID 类指标时必须明确 ID 来源和限制。

## 标注转检测框

v1 优先使用 CARRADA Range-Angle 标注 mask 的外接矩形生成检测框。若某些样本只具备点标注或稀疏标注，则允许使用配置化扩框策略生成检测框，但必须在转换记录中标记：

1. 标注来源类型，例如 `mask_bbox`、`point_expand` 或 `sparse_expand`。
2. 扩框参数。
3. 转换后的框是否被裁剪到图像有效区域。
4. 因标注缺失或非法导致样本被保留为空标注还是被过滤。

`object_id` 仅在原始标注能保证同一序列内实例 ID 稳定时用于跟踪评估。若无法确认稳定性，检测标注仍可生成，但 IDF1、ID switches 和 track fragmentation 等 ID 类指标必须在评估结果中标记为不可用。

## 类别定义

类别定义应由 `configs/dataset/` 下的配置文件管理，并在每次实验中复制到输出目录。检测标签、检测结果、跟踪结果和评估模块必须使用同一类别映射。

类别列表和 `class_id` 顺序一旦进入实验配置即视为冻结。任何类别合并、过滤或重编号都必须产生新的 dataset config，不能在训练、推理、跟踪或评估脚本中临时修改。

## 数据划分

v1 默认优先使用 CARRADA 官方划分。若官方划分不可用或不满足实验需求，才允许使用自定义划分。

自定义划分必须按 sequence 级别执行，避免同一序列的高度相似帧同时进入训练和测试造成评估污染。数据准备输出中必须保存划分文件、随机种子和生成规则。

## 标注转换检查

数据准备必须提供抽样可视化，用于检查：

1. Range-Angle 图像是否正常生成。
2. 标注框是否落在图像有效区域。
3. 类别映射是否正确。
4. 空标注帧是否被正确保留或过滤。
5. train / val / test 划分是否符合预期。
