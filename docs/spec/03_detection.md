# 03. 检测规格

## 检测目标

检测模块负责基于 CARRADA Range-Angle 输入完成 YOLO 训练和推理，并把模型输出规约为项目统一检测结果。后续跟踪、评估和可视化模块不得直接依赖 YOLO 原始目录结构。

## YOLO 实现

v1 默认使用 Ultralytics YOLO 作为检测器实现。具体包版本由 `pyproject.toml` 和 `uv.lock` 固化；实验配置必须记录模型或权重标识。

检测模块只能通过 adapter 读取 Ultralytics 的训练或推理输出，并转换为项目统一检测结果。其他模块不得依赖 Ultralytics 私有目录结构、文件命名或结果对象。

## 训练输入

训练输入来自数据准备模块生成的 YOLO 数据集目录和数据集配置。训练配置至少包含：

1. 数据集配置路径。
2. YOLO 模型或权重路径。
3. 输入尺寸。
4. 训练轮数或快速实验模式。
5. batch size。
6. 输出实验名称。

v1 的最小闭环优先保证外部权重或已训练权重的推理链路可运行。训练脚本必须保留，但训练成功不作为第一阶段闭环的阻塞条件；正式 baseline 发布前应补齐训练配置和训练日志归档。

## 推理输入

推理输入可以是训练得到的权重或外部已有权重。推理配置至少包含：

1. 权重路径，默认从 `weights/` 下解析，并允许通过配置覆盖。
2. 推理数据 split。
3. 置信度阈值。
4. NMS 阈值。
5. 输入尺寸。
6. 输出目录。

## 统一检测结果

检测模块必须输出统一检测结果文件。v1 统一结果默认使用 CSV，每条结果至少包含：

```text
sequence_id, frame_id, class_id, score, x1, y1, x2, y2
```

默认文件名为 `detections.csv`，并写入当前实验目录的 `detections/` 下。

坐标统一为图像像素坐标。`score` 使用模型输出置信度，取值范围为 0 到 1。

## 检测可视化

检测模块或可视化模块应能基于统一检测结果生成检测框图像。图像上至少显示：

1. 目标框。
2. 类别名或类别 ID。
3. 置信度。

检测可视化用于人工检查，不作为指标计算来源。

## 对比参数

v1 至少支持以下检测对比维度：

1. 不同 YOLO 权重或模型规模。
2. 不同输入尺寸。
3. 不同置信度阈值。
4. 不同 NMS 设置。

每次对比必须生成独立实验目录，并保存最终生效配置。

## 失败处理

检测模块遇到以下情况应显式失败并给出错误信息：

1. 权重路径不存在。
2. 数据集配置不存在。
3. 推理 split 没有样本。
4. YOLO 原始输出无法映射回 `sequence_id` 和 `frame_id`。
5. 输出坐标非法或超出图像范围且无法修正。
