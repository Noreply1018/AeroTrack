# AeroTrack

AeroTrack 是一个面向雷达感知研究的目标检测与多目标跟踪实验基线项目。

项目关注的不是单次模型演示，而是回答一个更完整的问题：给定连续的雷达序列，系统能否在每一帧中检测出目标，并在时间维度上持续跟踪这些目标，形成稳定、可评估、可复现的目标轨迹。

## 项目定位

AeroTrack 以 CARRADA 数据集的 Range-Angle 雷达表示为主要输入，目标是构建从雷达数据准备、目标检测、多目标跟踪、指标评估到可视化归档的完整实验闭环。

项目的核心任务规划包括：

1. 将雷达 Range-Angle 数据组织成可用于目标检测模型的数据格式。
2. 使用 YOLO 系列检测器在雷达表示上完成目标检测 baseline。
3. 将逐帧检测结果接入 SORT 跟踪器，生成序列级目标轨迹，并为 ByteTrack 预留同接口接入能力。
4. 统一检测结果、跟踪结果、评估指标和可视化输出。
5. 通过配置化实验目录保证结果可以复现、比较和审计。

因此，AeroTrack 本质上是一个雷达目标检测-跟踪实验平台，而不是单纯的 YOLO 调用脚本。

当前阶段优先跑通工程闭环和接口规约。`gt_bbox` 可作为诊断检测来源验证后续跟踪、评估和可视化链路，但不能等同于正式 YOLO baseline。正式检测 baseline 应以 YOLO 推理或训练产物为检测来源。

## 与普通 YOLO 项目的区别

YOLO 是本项目的重要检测器 baseline，但 YOLO 本身不是项目的全部创新点。

普通 YOLO 项目通常处理 RGB 图像，例如街景照片中的车辆、行人或交通标志。AeroTrack 处理的是雷达 Range-Angle 图，它来自雷达信号在距离和角度维度上的二维表示。它的目标外观、噪声分布、纹理特征和普通相机图像明显不同。

本项目要解决的是：如何把成熟的视觉检测方法迁移到雷达 Range-Angle 表示上，并进一步把逐帧检测结果接入多目标跟踪，使系统能够从“检测到目标”推进到“持续跟踪目标”。

## 项目特色与技术贡献边界

### 1. YOLO 在雷达 Range-Angle 表示上的适配

项目并不是重新发明 YOLO，而是将 YOLO 应用于非传统视觉图像的雷达 Range-Angle 表示。

这要求项目处理雷达数据转换、图像归一化、目标框生成、类别映射、坐标规约和实验配置等问题，使雷达数据能够进入通用检测框架，并产出可比较的检测结果。

### 2. 检测与多目标跟踪的一体化

AeroTrack 不止关注单帧检测结果，还关注连续帧之间的目标关联。

检测模块回答“这一帧哪里有目标”，跟踪模块进一步回答“这些目标在后续帧中是否仍是同一个对象”。这使项目更接近自动驾驶和智能感知系统中的实际雷达感知链路。

### 3. 统一的雷达感知实验基线

项目通过统一的数据接口、检测输出、跟踪输出、指标文件和可视化结果，为后续形成稳定的雷达感知实验基线提供基础。

在同一套口径下，可以比较不同 YOLO 权重、模型规模、置信度阈值、NMS 设置和 SORT 跟踪参数。ByteTrack 接入后，可进一步进行 SORT / ByteTrack 横向比较；未来也可扩展 Range-Doppler、Doppler-Angle 或多表示融合方案。

### 4. 从检测结果到失败分析的完整闭环

AeroTrack 在设计上不只关注指标数值，也强调可视化、轨迹回放和失败样例记录。

这有助于分析雷达目标检测中的漏检、虚警、跟踪中断、ID 不稳定等问题，使实验结果不仅能被量化比较，也能被人工复核和解释。

## 一句话概括

AeroTrack 的核心不是“用了 YOLO”，而是构建一套基于雷达 Range-Angle 表示的 YOLO 目标检测与多目标跟踪实验基线，用于研究通用视觉检测方法如何迁移到雷达感知场景，并评估检测结果对后续目标跟踪的影响。
